# Configuration

Every setting Pako reads, in one place. Local mode needs none of them.

## Settings reference

Local mode needs none of these. A hosted server takes them from its environment; local mode reads `~/.pako/.env` and `./.env` the same way. Every setting the
code reads must be listed here, in `docs/personal-caller.md` or in `assistant/README.md` (a test checks it).

| Setting | Default | What it does |
| --- | --- | --- |
| `PAKO_HOME` | `~/.pako` | Where local mode keeps its secrets, notes, reminders and chat. |
| `PAKO_SECRET_STORE` | `auto` | Where local mode keeps its secrets (the bridge token, the phone line's token, the panel's session key, the Telegram bot token, WhatsApp's values and the connections set in the panel). `auto`: in the system's secret store when there is one that works (the macOS login keychain, the Windows Credential Manager, or libsecret's `secret-tool` on a Linux desktop with a session bus, `DBUS_SESSION_BUS_ADDRESS`), else in `~/.pako/secrets.json` (mode 600). `keychain`: the same, but a store that cannot be used is reported at start. `file`: always `secrets.json`; secrets already in the store are moved back into it at the next start. Under the test runner (`NODE_TEST_CONTEXT`), or with a `HOME` that is not your account's own, `auto` means `file`. See [Where it is kept](privacy.md#where-it-is-kept). |
| `PAKO_NAME` | asked in the panel's welcome | What Pako calls you in local mode. With it set, the panel does not ask. Until a name is given Pako says *friend*. |
| `PAKO_LABS` | `off` | `on` turns on the parts still in Labs: the health diary (`MY HEALTH`, `log: …`), learning goals and quiz cards (`QUIZ ME`), and the weekly check-in. Off, Pako answers none of them and the assistant is told they are off. A red flag in your own words always gets the emergency answer, Labs or not. |
| `PAKO_COUNTRY` | the country of your time zone, else of your system's locale | Your country, two letters (`US`, `GB`, `IN`, `DE`…): the emergency number (911, 999, 112…) and the crisis line (988 in the US, 116 123 in the UK) Pako gives for a red flag, the country code of a phone number you write without one, and how dates and times are written (with `en`, 3:05 PM and 11/3 in the US, 15:05 and 3/11 in the UK). Pako has the numbers of US, CA, GB, IE, AU, FR, DE, IT, ES, PT, MX, AR, CO, CL and a few more (112 for the rest of the EU); for another country it says "your local emergency number" and findahelpline.com. See [Languages and countries](languages.md). |
| `PAKO_LANGUAGE` | ignored | Accepted and ignored, and the log says so once: Pako's own texts are English everywhere, and Claude answers in the language you write in. It can be removed. See [Languages](features.md#languages). |
| `ANTHROPIC_API_KEY` | empty (Claude uses your sign-in) | Your own Anthropic API key, for Claude without a plan. Passed to the `claude` command only, with Claude's other `ANTHROPIC_*` and `CLAUDE_*` settings. See [With an API key instead of a plan](install.md#with-an-api-key-instead-of-a-plan). |
| `PAKO_LOCAL` | automatic | `1` forces local mode, `0` turns it off. Automatic means on when neither WhatsApp nor the phone line is set up and not on Render. |
| `PAKO_HOST` | `127.0.0.1` | The address local mode listens on, and the only other name the panel then answers to. Leave it: the panel is for you only. With `PAKO_HOST=0.0.0.0` (or `::`) it also answers to this computer's network addresses and host name. Through an SSH tunnel or a container, keep the same name (`127.0.0.1`): another name gets a 421. |
| `PAKO_NO_OPEN` | empty | `1` stops local mode from opening your browser. |
| `PAKO_DEMO` | empty | `1` starts the demo week (also `npm start -- --demo`, or **Try with a demo week** in the panel): an invented week in `~/.pako/demo`, every connection off, nothing sent. **Leave demo** in the panel deletes it. |
| `PAKO_REPO`, `PAKO_APP_REPORT`, `PAKO_APP_UPDATE_FEED`, `PAKO_APP_FAKE_SOURCES`, `PAKO_APP_WALK` | empty | Only for the Mac app (`desktop/mac`): the Pako folder before any other it looks in, a path for a report of a build's check, a check-only update feed, made-up calendars, contacts and Mail accounts in place of the Mac's, and a walk through the connections page with a picture of each step (the last four ignored by a Developer ID build). See [docs/desktop-mac.md](desktop-mac.md). |
| `PAKO_APP_BUNDLE` | empty | Set to `1` by Pako for Mac for the server it carries inside itself: "start with this computer" then belongs to the app's own login item, and the panel's card and `--autostart` say so instead of writing a LaunchAgent that would point inside the app. Not for you to set. |
| `PAKO_APP_PID` | empty | Set by Pako for Mac to its own process id for the Pako it starts: that Pako stops by itself within two seconds when the app is gone without stopping it (Force Quit, a crash), and prints no sign-in link at start (its output goes to `~/.pako/logs/app.log`). Ignored under launchd/systemd (`PAKO_SERVICE`). Not for you to set. |
| `PAKO_SERVICE` | empty | Set to `1` by autostart's LaunchAgent or systemd unit: when Pako cannot start for a reason a restart cannot mend (another Pako holds the folder, the port is taken, a wrong setting), it then exits so that launchd or systemd does not start it again. Not for you to set. |
| `PAKO_PARENT_PID` | empty | Set by Pako itself when it starts the assistant's bridge (the bridge then stops when that process goes). Not for you to set. |
| `PAKO_LOG_LEVEL` | `info` | The lowest level the log writes: `debug`, `info`, `warn` or `error`. Each line says its level and the part that wrote it (`[whatsapp]`, `[pako]`…). The log never holds a secret: fields named like a token, secret, password, authorization, cookie, key or code, bearer tokens and API keys, the one-time codes of your mail, and phone numbers past their last 3 digits are hidden. |
| `PAKO_LOG_FORMAT` | `text` | `json` writes each log line as a JSON object (`ts`, `level`, `component`, `msg` and the line's fields) for a log service. By default the lines are plain text, as in `~/.pako/logs/pako.log`: `2026-11-18T09:30:00.000Z INFO [whatsapp] webhook: 1 queued`. |
| `ASSISTANT_NOTICE_MS` | `15000` | After how many milliseconds of thinking the assistant says "One moment…" (1000 to 120000). |
| `PORT` | 8787 | HTTP port (Render sets it). |
| `TRUST_PROXY_HOPS` | 0; 3 on Render (as measured) | Proxies in front of the app whose `X-Forwarded-For` is trusted, for the rate limits. |
| `ADMIN_KEY` | empty (admin routes closed) | Opens the `/admin` routes (the action log at `/admin/log`, voice lab, personal caller status, voices, agent sync) with Basic or Bearer auth or an `X-Admin-Key` header; at least 24 characters. |
| `RETELL_API_KEY`, `RETELL_FROM_NUMBER` | empty | Retell, for calls to friends and the `retell` engine. Without both, the phone line stays a dry run. |
| `PERSONAL_CALLER_TOKEN`, `PERSONAL_OWNER_NUMBER`, `PERSONAL_OWNER_NAME`, `PERSONAL_LIVE`, `PERSONAL_CONTACTS`, `PERSONAL_CONTACTS_EXTRA`, `PERSONAL_AGENT_ID`, caps and quiet hours | empty | The phone line; the full table is in [docs/personal-caller.md](personal-caller.md). Without the token the line, and WhatsApp with it, is off. |
| `AUTONOMY` | `direct` | What Pako does when you ask in your own words to send a message or an email, or to call someone with a message: `direct` does it after a few seconds with an **Undo** button on the receipt; `confirm` always shows a card first, as before. A card asks anyway when the recipient, the number, the address or the words came from someone else's text (an email, Slack, the calendar, the web, a forwarded message), when two contacts match, for money, purchases and deleting, and for anything Pako starts by itself. The panel's **How Pako acts** card sets the level for all three or each type apart (src/autonomy.ts). |
| `AUTONOMY_UNDO_SECONDS` | `10` | How long a direct message, email or call waits for **Undo** before it goes out (3 to 120); the panel's **How Pako acts** card can set each type apart. What is waiting survives a restart and is never sent twice. |
| `PERSONAL_CONTACT_EMAILS` | empty | The contact book's email addresses, as JSON (`{"Ana Lopez":"ana@example.com"}`): "email Ana that I'm running late" goes to Ana's. | `PERSONAL_ENGINE` | `retell` | `livekit` starts the owner's calls on the LiveKit engine; `set_engine` changes it at run time (a restart resets it). |
| `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` | empty | The LiveKit voice stack; with all three the `livekit` engine exists. |
| `LIVEKIT_VOICE`, `LIVEKIT_MODEL` | `Puck`; the model named in `src/voice-bridge.ts` | The Gemini voice and model for LiveKit calls; `set_voice` changes the voice at run time. |
| `VOICE_WORKER_URL` | empty | The voice worker's address, pinged to wake it before a call. |
| `VOICE_RESULTS_URL` | empty (memory only) | A Redis-protocol key value store (`redis://` or `rediss://`): call results, the owner's notes, the WhatsApp inbox and reminders survive restarts. |
| `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN`, `ASSISTANT_BRIDGE_TOKEN` and the other `WHATSAPP_*` | empty | The WhatsApp door; see [assistant/README.md](../assistant/README.md). |
| `WHATSAPP_GRAPH_VERSION` | `v23.0` | The Graph API version, moved when Meta retires one. |
| `ZOHO_CLIENT_ID`, `ZOHO_CLIENT_SECRET`, `ZOHO_DC`, `ZOHO_GRANT_CODE`, `ZOHO_REFRESH_TOKEN`, `ZOHO_CALENDARS`, `CALENDAR_REMIND_MINUTES` | empty (Zoho off); `eu`; 10 | The owner's Zoho Calendar, read only (`src/calendar.ts`): AGENDA, reminders before events, the brief's events; see [assistant/README.md](../assistant/README.md), "Calendar". `CALENDAR_REMIND_MINUTES` also applies to the ICS links. |
| `CALENDAR_ICS_URL` | empty | Any calendar by its secret ICS link (`src/ics.ts`): one or more `https://` or `webcal://` links, spaces or commas between them, 10 at most. Read with Zoho when both are set; see [docs/personal-caller.md](personal-caller.md). |
| `BRIEF_SMART`, `BRIEF_WAIT_MIN` | `on`; `15` | The written morning brief (`src/brief-v2.ts`): the assistant's computer writes it from your follow-ups, meetings, Slack, calendar, tasks and mail, every item citing its source; a short version on the chat and the full page at `/panel/brief`. `off` = the old brief only; without an answer in `BRIEF_WAIT_MIN` minutes the old one goes. ### The assistant's computer (`assistant/.env`, hosted way only)

| Setting | Default | What it does |
| --- | --- | --- |
| `ASSISTANT_SERVER_URL` | none (required) | The server's https address. |
| `ASSISTANT_BRIDGE_TOKEN` | none (required) | The same value as on Render. |
| `ASSISTANT_STATE_DIR` | `~/.pako-assistant` | The empty folder `claude -p` runs from, and the bridge's state. A Mac set up before Pako had its name, with only `~/.ai-buyer-assistant`, keeps using that one. |
| `CLAUDE_BIN` | `claude` | The Claude Code binary (on Windows a `claude.cmd` works too). |
| `ASSISTANT_MODEL` | `claude-sonnet-5-5` | Every run of Claude but the writing ones: your chat, follow-ups, mail summaries, verdicts, checks. `off` or empty: the default. |
| `ASSISTANT_WRITING_MODEL` | `claude-opus-5-5` | The morning brief and the drafts for a follow-up (a reply, an email). `off` or empty: `ASSISTANT_MODEL`. See below. |
| `BRIDGE_AUTOUPDATE` | `on` | The assistant's computer keeps itself up to date from GitHub (`assistant/update.ts`): `off` to update it by hand. See [assistant/README.md](../assistant/README.md), "It updates itself". |

The brief is about one run a day and the drafts a few, so they get the stronger model and the frequent, fast work stays on Sonnet. When
your plan cannot use the writing model (not included, not there, or its own limit reached), that run goes again on `ASSISTANT_MODEL` at once,
with one line in the log, and the writing model is set aside until the next day: the brief never fails for the model. The day's numbers in
the log (`claude today: ...`) say how many runs each model answered.

In local mode these `ASSISTANT_*` settings go in `~/.pako/.env` (the server passes them to the assistant it starts). The rest (the Whisper
settings, the budget) is in [assistant/README.md](../assistant/README.md).
